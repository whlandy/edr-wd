# 正常基础操作的完整录制与可靠回放：统一补齐设计

版本：R1。日期：2026-11-06（上海时间）。状态：设计已合并；交原 CC 按有限功能片实施并建立定时接续。本文不是实机验收通过声明。

## 1. 用户目标与范围优先级

用户要求：语言切换、菜单开合、返回主窗口、窗口移动等正常操作应当能完整、流畅地录制和正确回放。不能用“别切语言”“别拖窗口”“慢一点”“只录 Log Center→Refresh→回来”代替功能。简化流程仅用于定位单一原因，不能成为最终验收流程。

本文件合并：

1. 上一轮未完成的采集完整性/流畅度、布局拖拽策略、弹出菜单实例身份、缺菜单快照及真实 Windows 闭环。
2. 当前语言切换暴露的无 automationId、翻译/动态标签、几何变化、同名短生命周期窗口及结构定位实际注入问题。
3. 具有相同根因的基础操作，按 §9 的有界状态与变异覆盖，不无限增加功能。

**产品优先级：正常操作可用 + 录制事实完整 + 操作流畅。** 身份、租约、脱敏与 unknown 安全边界用于防误操作，不应被当作“产品不需要补功能”的理由。正确拒绝只验证负例，不等于对应正向能力交付。

## 4. 唯一主链与基本状态模型

只修补现有链：原生输入/生命周期 hook → bounded queue → correlator/session → 停止持久化/必要收集 → 真实 compiler → 普通 materializer 或既有受控v3 adapter → 同一 server/policy/binding/dispatcher → 既有断言求值 → attempt账本 → 精简报告。

不手造成功receipt/StepResult/阶段结果，不复制新业务循环；OS替身仅用于本地适配测试，不称实机。

| 状态 | 应维护事实 | 转换与不变量 |
| --- | --- | --- |
| Recording | 本次scope/RI、输入接收序、当前语言、菜单/窗口可见段、队列/相关错误、快照来源 | 语言改变的是显示/设置状态，不应无故改变目标app归属；每个业务手势可追溯 |
| Stopping/Collecting | 停止已执行与持久化成功分开、待处理事件/快照有界收尾 | 必要存储/收集失败则后续compile/replay不运行，原件可只读重连 |
| Compiling | RI→W、动作/断言/效果角色、控件策略与证据缺口 | 能力误报应修，真实缺口保留；不以status开关、补假字段凑ready |
| Bound/Dispatching | 本次绑定/代际、当次控件、同一租约/串行边界 | 不用旧坐标/handle/token；检查至派发不释放安全边界 |
| Verifying | 动作receipt、窗口/布局结果、独立业务断言 | 三类结果分别表达；任何必需项未知/失败不推进 |
| Reporting/Restart | 稳定attempt/前步ref、本次特征、匹配策略、动作和断言结果 | append-only、同源refs、脱敏、重启仅重建；不自动恢复未知GUI |

## 5. D1：先保证录得全、录得顺

### 5.1 输入与损失语义

必须区分：业务手势、原生包、正常合并、明确非目标事件、已确认目标输入/生命周期损失、未归属生命周期事件、关联错误、录制控制面板输入、真正遮挡目标输入。**未归属不自动等于环境噪音，也不自动等于目标丢失。**

- 追到真实producer→source→session→raw/schema→compiler诊断。当前新增明细若仍计入总量，要把兼容语义与新判定明确列出，不能在一层说“已剔除”而底层仍混算。
- 全局hook未记忆的DESTROY可能来自其他进程，也可能是目标漏SHOW/启动竞态；不能仅以无缓存判noise。使用本run的进程域/启动代际、初始枚举、owner/parent与原生订阅来源证明归属；必要时按已授权目标进程过滤订阅，并处理子进程/重开，不能漏掉弹窗。
- 原始计数不删改；给新录制保留可解释分类与未知范围。老raw只有聚合计数时保留旧含义和不确定性，不批量减计数后称修复。
- 完整性指每个接受的业务手势及必要生命周期都有来源/归并解释；不是要求每个mousemove都生成独立业务步骤。scroll/双击等合法合并保留source映射。
- start/stop控制输入与遮挡目标输入分开。面板输入不伪装业务步骤，正常录制控制不无条件污染整份业务录制；真正拦截/漏收目标动作则如实诊断并修面板交互。

### 5.2 短生命周期菜单的快照

- 在菜单SHOW/目标进入等实际可观察时机优先采集有界菜单子树，缓存键包含session/RI/代际/可见段；不得仅按title/native handle重用。
- 点菜单后菜单可能立刻隐藏，不能只依赖动作后后台全树扫描。处理SHOW→输入→HIDE与后台发布的竞态，发布前校验实例仍属于原可见段；失效结果不挂到新菜单。
- 子树complete只能说明明确作用域内的全部相关兄弟项，不冒充整应用完整。完整性字段、scope、引用和schema/model/reader必须一致。
- 缺失的旧帧不可回填成事实。新录制必须实际产生当前菜单特征；验收包含先前“第4次语言菜单丢帧”的完整序列，不以删除第4次点击过关。

### 5.3 流畅度与停止收尾

- 原生hook只做最小记录与入队，不同步遍历UIA、不编码截图、不在callback等待网络/锁。
- 同一事件的诊断与归属共用事实，不为trace重复查询OS窗口。缓存不能把上一事件/上一实例当本次事实；失败回退也要计数与解释。
- 菜单局部观察、慢全树扫描、图片等任务分清优先级和取消/过期策略；不靠无限加队列、无限等worker或用户“放慢操作”掩盖问题。
- 采集队列高水位、enqueue→处理延迟分布、UIA调用次数/耗时、停止drain耗时及实际丢包分类。先测当前环境基线，再固定有依据的回归预算；未测数值不得写“达到零延迟/零丢包”。
- 正常操作速度和快速但合法的菜单开合都要覆盖。不得把刻意省掉语言/拖拽的流程作为流畅度最终验收。

## 6. D2：语言切换与弹出菜单可靠身份

### 6.1 控件策略

1. 稳定automationId/identifier可用时继续优先，翻译文本只作描述或业务结果，不反向加约束。
2. 无ID时复用B1显式 `menu-layout/v1`：限定菜单项、父层级与完整同级布局，使用局部归一化几何，不能只凭绝对rect或删name后“剩一个就点”。当前2–64项/2%为已实现策略参数，不是所有UI通用常数；只按反例调整，不无边界放宽。
3. 解析的是本次观测里的真实target；实际注入参数必须来自该target的当前文本/唯一原生ID。普通materializer与受控v3链同契约，不能仅helper能解析而dispatcher仍发送Language或空参数。
4. 结构改变、多个不可区分候选、缺完整性或证据冲突时不乱点。位置同形不总证明业务同义：同几何项重排/命令替换等必须在当前公开可观测的原生菜单身份、父菜单/command信息或预定义业务结果中找到判别依据；没有依据就明确该项未证明，不称“语义唯一”。不能靠本轮输出学习期望。
5. 动态计数/时钟、业务列表内容变化与翻译标签分别建模。不是所有Text/Button都可忽略name；列表排序后的旧屏幕位置不能代表同一业务对象。

### 6.2 窗口策略（补齐当前真正阻断点）

- 顶层菜单/子菜单可能同进程同title、无root、反复销毁重建，甚至同时可见。使用真实owner/parent、菜单层级、所属主窗口及生命周期段作为可验证证据；录制RI、golden引用、本次运行binding仍严格分开。
- 单个RID段内的SHOW/HIDE与DESTROY/新实例不能混同；父菜单与子菜单不能因为EDRClient标题相同合并。native owner/parent只作本次关系证据，不作跨run固定handle。
- 对已有flat-selector碰撞诊断，区分确实同时不可区分与已有生命周期/owner证据可执行的菜单链。能解除误报则最小修；不能仅删compile_window_identity_ambiguous或把所有菜单归主窗口。
- 每次首次绑定要有声明的可执行唯一策略；同名兄弟共存时通过真实父链/代际/候选差分等证据定位，不挑最近前台/枚举第一个。LOST不选兄弟替代。
- 允许title-only与无ID菜单成为合法可用路径，缺强ID不是产品不实现的理由。需要新增关系契约时同步模型/schema、能力、编译、运行、报告及导出；不强迫用户修改被测app才能录制基础功能。

### 6.3 语言结果不是“点到了就行”

完整流程验证当前语言设置/所选值和界面结果，再继续Log Center/Refresh/返回等正常操作。期望来自用户规格与公开UI校准后固定；不在运行时把实测值当期望。菜单存在/receipt ok不能代替语言已切换。

最小必测：English→中文→Spanish→返回初始语言；原件中的反复打开菜单和末次点击保留。B1的French属于本地泛化用例，不据此声称任何语言/任意布局实机已通过。

## 7. D3：拖拽按操作语义分型，而非“一律数据断言/一律豁免”

| 类别 | 录制与识别依据 | 回放及结果 |
| --- | --- | --- |
| 移动顶层窗口 | 起点确属该窗口caption/标题栏，实例/owner一致；记录前后bounds、坐标空间和状态 | 本次绑定下执行；位置变化是布局结果，不要求业务数据变化 |
| 调整窗口/分隔区域尺寸 | 起点为可验证resize/分隔句柄，关联窗口/面板几何 | 验尺寸或区域几何，不拿window_open代替 |
| 数据/组件拖拽 | 起点/终点属于列表、表格、树、设计对象等 | 保留目标内容/顺序/对象状态等业务结果验证 |
| 尚未分型 | 特征不足或互相矛盾 | 补采/诊断，不因endTarget带title字样就升级布局豁免 |

现有 `_is_layout_drag` 仅看终点titleWidget/title存在误分类风险：**从数据对象拖到标题栏**不是移动窗口；本片需成对反例。起点、所属实例、原生hit-test/公开UIA窗口模式和前后几何应相互印证，不只看字符串或位移大小。

策略分层：

- 任何receipt未知、绑定失效或实际数据断言失败仍unknown/fail并阻断，不能因“非关键布局”清除。
- 用户允许的附带布局动作可声明action-only/advisory验证范围：确定动作已执行、身份仍可信时，不因缺无关数据断言中断整流；报告必须写“已执行/位移未验证”，不得伪写“位置已改变”。
- 若明确声明必须移动/缩放，则实际几何结果未满足必须失败；合法边界无变化（如最大化/屏幕边缘）先用公开行为校准，不把所有no-op当通过。
- 必要验证、可选观测与整步outcome分开。可选布局观测未取得，不等于GUI执行结果unknown；后者仍按09阻断。新增范围字段/验证器必须版本化对齐既有模型，不能复用window_open冒充几何验证。
- 记录所有动作；不静默删除drag、追加假assertion、清verifiers或重写原件以凑ready。

## 8. D4：同类基础操作的有限扩展

以下只覆盖与现有根因相连的操作，不新造产品模块：

- 设置入口/菜单/子菜单：标签本地化、无ID、菜单自动关闭、父子菜单同名、重开新实例。
- 状态型按钮/开关/下拉框：同一控件显示文案/选中值变化；定位与结果值分开；重复设置同值的合法no-op不重置业务状态。
- 列表/表格：滚动/虚拟化后候选变化、同名行、排序改变；继续用实际对象/内容证据，不把旧行号或坐标当业务身份。
- 窗口布局：移动/缩放、已有DPI/显示器坐标空间变化后仍命中本次控件；本地用变换fixture，真实修改系统显示设置需单独授权。
- 弹框与遮挡：前台合法变化、modal阻挡、同名兄弟仍在、原绑定消失；不能借“恢复流畅”自动关别的窗口或重新点一遍。

基于同一正常流做单变量变异（语言/几何/实例/可见性/速度/队列/输入归属），仅对强相关因素叠加双变量（例如换语言后重开菜单、移动窗口后再开子菜单）。不做所有语言×DPI×窗口×故障的无界笛卡儿积。
