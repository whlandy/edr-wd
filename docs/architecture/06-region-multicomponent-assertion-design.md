## 2. 用户操作流程

1. 录制中或已暂停时按 Ctrl+Shift+Q。校验当前录制会话和目标窗口；隐藏录制面板和浮窗，显示可取消的半透明选区层。
2. 拖出矩形区域。高亮区域内可识别组件，提供“选择整个容器”和逐个增选/取消组件；列表优先给出容器及行、列结构。框选几何只用于选择，不直接作为永久组件身份。
3. 展示已选组件的名称、类型、当前可读内容，以及所属窗口。读不到时明确显示无法读取，不能自动补空值。
4. 配置“查找什么”和“怎样才满足”：文本、状态、存在性、数量、时间，及全部/任意组合关系。对于列表提供“任意一行满足”表单。
5. 配置时间：关联动作、观察时长、内容时间范围。界面持续显示完整中文摘要，时间阈值和等待时长分别编辑。
6. 预览只读匹配结果，标明匹配行及未满足条件；保存后收到后台成功回执才关闭。Esc 取消并恢复进入前录制状态。

快捷键只是统一入口，不能消除动作归属选择。向导中展示待关联动作的序号、描述和时间，用户确认后绑定；允许选择独立检查点。最近动作可作为候选，不能保存时静默绑定当前最后一个动作。

## 3. 条件与目标模型

| 维度 | 拟支持条件 | 表达方式 |
|---|---|---|
| 内容 | 等于、包含、不包含、正则 | 字段及可编辑期望文本 |
| 存在性 | 存在、不存在符合条件的项 | 容器范围内查询 |
| 数量 | 等于、至少、至多 | 满足条件的项数 |
| 状态 | 可见、可用、勾选及对应否定 | 仅提供平台可可靠读取的状态 |
| 时间 | 时间区间、相对动作时间、相对当前时间 | 明确锚点、前后阈值、时区 |
| 组合 | 全部满足、任意满足 | 明确分组及同一项约束 |

多选有两种不同含义，界面应明确：

- 固定多个组件：例如标题包含某字且复选框已勾选，可按全部或任意组合。
- 查询容器中的动态子项：例如列表中存在一行，名称、状态、时间同时满足条件。选中的示例行用来指定字段，不把它的行号或临时 runtime ID 固化为后续目标。

列表必须在同一行内完成条件合取，再对行集合做存在性判断。禁止“第一行名称正确、第二行状态正确、第三行时间正确”拼接成通过。刷新排序、增删行、控件重建后重新解析容器及项；保留目标窗口归属保护。虚拟列表只能确认当前可访问数据，不能把不可见且未加载行当作已搜索，也不能擅自滚动或点击刷新。

## 4. 时间语义（用户已确认）

三个概念分开保存与显示：

- 动作时刻 T：例如用户点击刷新的事件时间。
- 内容时间条件：列表项时间应落入哪个范围；默认锚点为每次检查当下，取最近5秒。
- 观察时长：默认 1 分钟，可修改；与内容时间阈值独立，不能互相替代。

用户确认：

1. 以每次检查当下为基准，默认检查内容时间是否属于最近5秒。设该次检查时刻为 C，则默认接受区间为 [C−5s, C]。每次采样重算区间，不固定在点击刷新时刻，也不接受未来时间；若需时钟容差应显式配置，不能默默扩宽。
2. 默认最多观察1分钟，找到一次满足全部条件的列表项就通过，不要求观察满一分钟或持续保持。1分钟内始终找不到则失败；读取错误导致无法下结论时保留不可判定证据。

默认摘要示例：“执行刷新后，最多观察1分钟；列表中任意一行同时满足名称包含‘目标内容’、状态等于‘成功’、该行时间位于本次检查当下最近5秒，即通过。”其中1分钟和5秒均可独立修改。观察从关联动作完成后开始；设置向导和预览所耗时间不扣入回放观察期限。首次匹配通过依赖同次行快照中的全部条件，不能跨时刻拼接。

存在/不存在需要不同完成规则：存在可在首次匹配时完成（若用户选择该模式）；“整个观察期都不存在”必须观察到期才通过，不能首帧无匹配就通过。若要求最终不存在或先出现后消失，应独立表达，不能隐式推断。

所有时间显示明确单位；正文摘要不写死 10s。建议允许输入秒/分钟，默认 60s；内容时间默认阈值 5s。采样频率属于内部执行策略，不让用户将其误认为时间阈值。用单调时钟计算观察期限，用带时区墙钟解析内容日期；相对时间在回放时重算，不能冻结录制当天日期。解析失败、日期缺失、时区不明或时钟偏差无法确定时返回不可判定并展示原文。

## 5. 拟议内部契约与实现边界

持久化至少包括：目标窗口身份、容器稳定选择器、组件/字段关系、条件树、行级量词、显式动作绑定、内容时间锚点及阈值、观察模式及期限。此为语义约束，具体 schema 需审查现有编译器和回放器后确定；不能只给 UI 增加未被回放消费的字段。

录制、预览和回放共用同一查询与比较语义。匹配结果区分通过、不满足、不可判定；未读取成功不能参与比较。保存时校验组合条件及类型，保留用户期望与当前观测的区别。不得手改 golden 来伪造支持。

选区期间鼠标、快捷键和向导操作属于管理输入，不进入业务动作；不穿透点击到被测应用。失败、取消、目标消失和服务断连都必须清理遮罩、释放快捷键并恢复此前状态。Windows/RDP的快捷键投递、多屏坐标、DPI缩放和冲突需实测；注册失败要明确告知，不能悄悄改键。跨窗口多选暂不默认允许，需沿用目标窗口范围和身份校验。

区域无可识别组件时说明原因；OCR/图片匹配是另一种能力，当前不承诺自动支持或伪装成组件断言。是否纳入后续范围需单独确认。

## 6. 验收设计

- Ctrl+Shift+Q实机弹出遮罩；Esc恢复；不会触发业务快捷键或录入伪动作。
- 多选组件可增删且高亮与身份一致；选区/窗口失效明确失败。
- 第一行不匹配而第二或第三行满足时通过；跨行拼接反例失败。
- 同名行、排序变化、控件重建、空列表及虚拟列表范围均有可解释结果。
- 默认5s/1min正确显示，分别修改后真实执行生效；边界、超时、时间解析失败有证据。
- 按已确认的首次匹配模式，覆盖首次满足、晚于期限满足、短暂满足后消失及完整观察期不存在等反例。
- 预览、真实录制和真实回放结果一致；原始采样/匹配证据、动作绑定、截图和hash可追溯。
- 旧录制兼容、旧两个入口移除、保存失败保留表单且重试不重复写入。
