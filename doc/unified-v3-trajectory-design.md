# EDR-WD 统一 v3 轨迹设计方案

日期：2026-11-10。状态：**待用户审核，尚未开始代码实施**。

本文件收敛并取代设计13/14中关于对外轨迹分类与版本选择的提案；原件保护、必要信息完整、真实断言、append-only与unknown阻断原则继续有效。

## 1. 最终决策

**新生成的主轨迹全部统一为 v3，简单和复杂流程使用同一种格式。**

- 唯一原生执行契约：`edr.desktop-golden-trace/v3`。
- 不再默认平行生成 golden v1、v2、v3，不让 Skill 挑版本或找“哪份能运行”。
- 一次真实采集、一次事实整理、一个主轨迹，再派生操作说明、MAA产物和报告。
- 旧v1/v2只作兼容导入；不得修改历史原件冒充新v3。
- 用户审核本文件后再实施；本文件不授权部署、GUI操作、清理原件或创建定时任务。

## 2. 你需要的三种用途如何统一

| 用户用途 | 对应入口 | 来源与边界 |
| --- | --- | --- |
| 原子步骤的操作描述 | `views/steps.md`；Skill可取结构化步骤视图 | 从主v3及同次编译的来源/缺口映射渲染，不独立维护另一套动作序列 |
| EDR-WD录制与回放 | `trace.v3.json` | 唯一主轨迹；既有真实采集、编译、受控执行链统一消费 |
| MaaFramework/maa-fw操作 | `exports/maa/pipeline.json`及必要资源 | 从同一主v3生成目标runtime投影，不再重新录制、手写或维护第二条业务逻辑 |

这里统一的是**轨迹事实与原生执行契约**。操作说明是视图，MAA节点表是目标格式导出，不是又一份并列的v1/v2/v3主轨迹。

MAA文件必须遵守目标runtime真正支持的格式，不能仅把其schema字符串改成v3而破坏兼容。内部raw采集协议也不是用户需要选择的另一种执行轨迹：保留原始证据与真实schema，不为名称统一而篡改它。

未被编译成可执行步骤的原始操作，必须在操作视图中显示为明确gap并链接sourceEventRefs；不能只遍历v3已成功编译的steps就宣称全点覆盖。复用现有全点提取和来源映射，不新造执行循环。

## 3. 简单流程也用v3，但不承担不必要的复杂成本

- 单窗口：只声明一个W，所有步骤归属该W；只保留实际需要的入口身份和断言。
- 多窗口/菜单：按真实实例声明多个W，记录步骤归属、转换依据、必要效果与清理。
- 不为了满足格式而虚构窗口转换、父子关系、业务断言或截图。
- 由内容推导所需能力，不靠调用方勾选“简单模式”绕过复杂步骤检查。

同一个执行器内减少无意义准备：没有窗口效果就不轮询效果；同一有效绑定不重复初始化；本次权威验证已确认前台与身份时不重复激活。动作前身份、租约、目标与派发检查不能省，不另建一套不校验的“快速v1执行器”。

## 4. 完整性、时间、体积的优先级

> 语义正确与必要信息完整 → 首次录制成功及总处理时间 → 存储体积。

优化目标是录制、停止收集、编译、回放验证、修复重录的**总时间**，不是把一次停止操作做得很快但留下缺口。

### 4.1 尽量第一次就采全

1. 输入hook只做轻量原生事件/窗口stamp/时间顺序入队，不等待UIA全树、图片编码、网络或LLM。
2. 新窗口、短命菜单、语言切换、tab变化、拖拽/滚动边界、关闭窗口优先获取必要上下文，不能被普通去抖或帧数上限静默吞掉。
3. 尽量保住真实按下时的窗口与目标观测；释放时窗口已消失不能把桌面识别成原目标。缺失时如实记录gap，不补造事件。
4. 录制中及时发现队列压力、窗口覆盖或目标证据缺口；仍可观察时做有上限的只读补观测，不偷偷重放业务输入。
5. 停止后排空必要事件并确认持久保存、读回和资源校验，再发布产物状态。不能提前返回假成功。

“完整”不是全程录屏或收集整个桌面，而是足以重现、验证和追查本流程所需的事实。无法保证任意应用100%一次成功，但已知基本操作不能靠建议用户避开来通过。

### 4.2 在不丢信息的前提下减容

- raw原件一份、主v3一份；协议回执/报告引用它们，不重复内嵌整份轨迹。
- 图片和必要模板按完全相同的字节hash去重；本次观测的窗口、时间、attempt与脱敏元数据各自保留。
- 稳定语义定位无需强制每步截图；视觉/OCR和短命状态需要的真实动作前图不能省，不做有损压缩。
- 控件上下文有有效实例/revision新鲜性依据才复用；不把旧缓存冒充本次识别。
- 默认不再重复生成case、pytest、三份完整报告或不同版本golden；兼容导出明确请求才物化。
- MAA导出/额外人读视图可增量或后台生成，不阻塞已就绪的原生入口；选择MAA时仍须等待它自己的完整支持与验证状态。
- 容量不足先保护必要事件、减少可再生工作并告警；不能静默丢包后仍称完整。

## 5. 一个文件夹，一个Skill入口

```text
<EDR_WD_RECORD_DIR>/trajectories/TRJ-<id>/
  manifest.json                      # Skill唯一发现入口，指向当前REV
  README.md                          # 三种用途、状态、报告的直达链接
  revisions/REV-<id>/
    trace.v3.json                    # 唯一主轨迹
    source-map.json                  # raw事件→v3步骤/明确gap
    views/steps.md                   # 原子操作说明
    exports/maa/pipeline.json         # MAA投影
    exports/maa/capabilities.json     # runtime模式、支持/缺口、来源hash
  sources/REC-<id>/                  # 原始采集、停止/持久化/收集回执
  assets/sha256/                     # 共享的真实脱敏资源
  runs/RUN-<id>/                     # 每次执行账本、summary与报告
  recovery/JOB-<id>/                 # 修复、重录与新run关联
```

名称不能代替唯一ID；同名录制不覆盖。修订不可变，manifest指向当前修订，不在顶层再复制一份。重复生成同一来源/参数的产物幂等，但新的执行attempt仍有独立记录。

所有资源与报告使用本夹相对路径，整夹复制后仍可校验、读报告和定位资源。Skill始终先读manifest：解释流程取steps视图，EDR-WD执行取主v3，MAA执行取其投影，不按目录中哪个文件名字像轨迹来猜。

## 6. 必须先打通的消费能力

当前代码已有v3模型与受控执行链，但公共回放仍有v3拒绝门；现有MAA转换器只接收旧golden v1。因此顺序必须是：

1. 修正既有transport/run绑定/unknown语义问题，复用已有可靠载体，不新增第三套。
2. 公共CLI、Skill及测试入口调用同一v3受控执行能力，保留所有安全与断言契约。
3. 扩展权威MAA转换器，真实接收v3并保持窗口归属、参数、断言、清理与来源。
4. 简单及复杂流程验收后，默认新写只输出v3；不能只删拒绝判断或改schema名称就切换。

### MAA不能只“能加载”

- 每个动作、窗口约束、必需断言都必须有执行实现；放进attach或scope注释不算执行。
- runtime原生支持全部契约时使用纯MAA；复杂桌面能力可通过现有executor/verifier缝隙桥接EDR-WD，明确标注依赖，不称纯MAA。
- 同一动作只有一个派发者，GUI租约唯一；unknown不自动重试，失败必需断言不能被on_error跳过后算通过。
- unsupported不得悄悄变DoNothing。缺能力保留完整映射和blocked诊断，实施阶段必须补齐目标场景，不能长期用拒绝代替功能交付。
- maa-fw节点runner与官方MaaFramework引擎分别标明runtimeId/version，不能用一个的替身测试冒充另一个的实机结果。

## 7. 旧资产与结果判定

- v1/v2仅保留兼容读取与显式转换，不默认继续写新版本。
- 能凭现有事实转换的，生成有来源的新v3修订；证据不足的复杂轨迹明确缺口，不虚构历史时间线，不强制抹掉旧资产。
- raw、失败记录和审计原件不覆盖；迁移先dry-run、复制、校验、发布，删除另行确认。
- 编译ready、实际回放pass、MAA导出成功、MAA实际业务验证pass分别记录。原生通过不代表MAA通过。
- 默认报告按本步特征→匹配→动作→断言→结果展示；previousAttemptId引用同一历史记录，真实before/after继续区分。

## 8. 实施与验收

| 阶段 | 目标 | 验收出口 |
| --- | --- | --- |
| A | 采集关键状态、关闭竞态、短命菜单与耗时基线 | 已知基本流程不漏点，错误可追溯，不靠避开操作 |
| B | 唯一v3消费链覆盖简单与复杂流程 | 原来正常的语义/视觉/单窗口不回退，跨窗口与断言真实通过 |
| C | 单夹布局与三种用途投影 | Skill只用一个manifest；来源映射完整，无并列golden v1/v2/v3 |
| D | MAA转换、桥接及真实验证 | 完整动作与必需断言实际执行，不是能加载/仅导出 |
| E | 无损去重、历史兼容与可选迁移 | 相同事实更小，不同事实不丢，搬动目录后仍可消费 |

固定样本覆盖简单点击/输入、语言菜单、日志tab和关闭、布局/数据拖拽、滚动、视觉定位，以及响应丢失、写盘失败、同名窗口替换负例。

分别测首次完整采集率、首次编译就绪率、首次业务回放通过率；测hook/关键上下文/停止收集/编译/原生就绪/MAA就绪/修复总时间的P50/P95；同时核对逻辑/物理字节和重复资源。先测基线再定硬件相关阈值，不凭空承诺秒数和节省率。

必须检查全点source-map、动作参数、窗口归属、必需断言与cleanup；未知/失败不许算通过。固定快照跑原两道完整pytest及显式需求/legacy回归，实际消费者验证与OS替身测试分列。

最终成功标准：**录制尽量一次完整成功；只生成一个v3主轨迹；同一份事实能解释步骤、由EDR-WD回放、由已标明的MAA runtime操作；报告和资源都在同一文件夹，且体积与总耗时下降没有损害信息完整性。**

## 9. 审核后开工边界

用户确认后按A→E分片实现与验收，允许调整必要接线顺序，但不扩大为AW平台、全面重构或新增执行器。复用原采集/收集/编译/执行/账本；不创建定时任务、子代理或新会话，不自行部署/提交推送/删除历史。此刻只交付设计，等待用户审核。
